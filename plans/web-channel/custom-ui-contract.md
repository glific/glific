- `interactive_message_type_enum` gains **one** value: `custom_ui` (the template type).

Migrations use the `20260715085249_add_web_message_flow_type.exs` pattern
(`@disable_ddl_transaction true`, `@disable_migration_lock true`, `ADD VALUE IF NOT EXISTS`).

## 2. The stored template payload (`interactive_templates.interactive_content`)

```jsonc
{
  "type": "custom_ui",                  // REQUIRED: existing plumbing derives the message
                                        // type from interactive_content["type"]
                                        // (contact_action.ex:109)
  "version": "1",                       // envelope version
  "component": "glific/image_panel",    // namespaced component name
  "props": { },                         // schema-checked for glific/*, opaque otherwise
  "fallback": "Pick a course: …",       // REQUIRED plain text, translatable
  "context": { }                        // OPTIONAL, echoed back verbatim
}
```

`type` is part of the stored payload only because Glific's existing interactive plumbing reads
it; conceptually the envelope is the other five fields.

**Translations.** `interactive_templates.translations` keeps its existing per-language-id shape.
For `custom_ui`, the translated payload is the same envelope with a translated `fallback` (and
any translated strings inside `props`).

## 3. Outbound: backend → widget

`MessageSerializer.serialize/1` output for a custom_ui message:

```jsonc
{
  "id": 4211,
  "body": "Pick a course: …",           // == fallback text
  "type": "custom_ui",
  "flow": "outbound",
  "inserted_at": "…",
  "media": null,
  "interactive_content": {
    "type": "custom_ui",
    "version": "1",
    "component": "glific/image_panel",
    "props": { },
    "fallback": "…",
    "context": { },
    "answered": false,                   // added on response receipt
    "answer_summary": null               // added on response receipt
  }
}
```

`answered` / `answer_summary` are written INTO the outbound message's stored
`interactive_content` when the response is accepted, so `serialize/1` stays a pure map read
(no per-message query — history fetches a page at a time).

## 4. Inbound: widget → backend

Socket event name: **`custom_ui_response`** on topic `web_channel:<contact_id>`.

```jsonc
{
  "message_id": 4211,                    // the outbound custom_ui message being answered
  "component": "glific/image_panel",     // echo
  "values": { "course": "c2" },          // keyed by ids from props
  "summary": "Picked Digital skills",    // REQUIRED plain string
  "context": { }                         // OPTIONAL echo
}
```

Reply convention follows the existing channel: `{:reply, :ok, socket}` or
`{:reply, {:error, %{reason: "…"}}, socket}`.

### Persisted inbound message

- `type: :custom_ui_response`
- `body:` the `summary` string (this is what renders in history and the staff inbox)
- `context_message_id:` the outbound message id (correlation; no new column needed)
- `channel: "web"`, `flow: :inbound`, `bsp_status: :delivered`, `status: :received`
- `interactive_content:`
  ```jsonc
  { "type": "custom_ui_response", "component": "…", "values": { }, "summary": "…", "context": { } }
  ```

## 5. Flow results

New clause in `router.ex`'s `update_context_results/4` cond, alongside `[:quick_reply, :list]`:

```elixir
msg.type in [:custom_ui_response] ->
  json =
    default_results                                  # "input" (= summary), "category", "inserted_at"
    |> Map.merge(normalized_values)                  # the whole values map, flattened in
    |> Map.put("summary", summary)
    |> Map.put("component", component)

  %{key => json}
```

`normalized_values` follows the webhook normalization rule: nested maps kept, lists become
index-keyed maps. So `@results.picker.course` == `"c2"`, `@results.picker.summary` ==
`"Picked Digital skills"`, `@results.picker.input` == the summary too (default_results).

Reminder: the expression parser resolves at most 5 dot-segments — keep values flat.

### Routing (no new case operator)

`find_category/3` (`router.ex:325`) falls through to `router.default_category_uuid` when no case
matches. The floweditor branch therefore emits **zero cases and a single category "Responded"
that is the router's default** — mirroring how `location_request_message` is built. Any
`custom_ui_response` (and any text reply from a non-web contact) takes that exit.

## 6. Built-in block schemas (`glific/*` — permanent)

Component names must match `^[a-z0-9_]+/[a-z0-9_]+$`. The `glific/` namespace is reserved:
a `glific/<name>` not in this catalog is rejected at template save. Any other namespace
(`tap/*`) is opaque — envelope validation only.

### `glific/image_panel`

```jsonc
{
  "id": "course",                        // REQUIRED — the key the answer lands under
  "body": "Hi @contact.fields.name, pick a course",   // OPTIONAL prompt text
  "options": [                           // REQUIRED, 1..10
    { "id": "c1", "image": "https://…/english.png", "label": "Spoken English" },
    { "id": "c2", "image": "https://…/digital.png", "label": "Digital skills" }
  ]
}
```
- Renders: grid of tappable images with labels, single-select.
- `values`: `{ "<props.id>": "<selected option id>" }`
- Auto summary: the selected option's `label`.

### `glific/carousel`

```jsonc
{
  "id": "product",
  "body": "Browse our courses",          // OPTIONAL
  "cards": [                             // REQUIRED, 1..10
    { "id": "p1", "image": "https://…/a.png", "title": "Course A",
      "description": "Six weeks, evenings" }
  ]
}
```
- Renders: horizontally swipeable cards (image, title, description) each with a select action.
- `values`: `{ "<props.id>": "<selected card id>" }`
- Auto summary: the selected card's `title`.

### `glific/form`

```jsonc
{
  "id": "signup",                        // OPTIONAL (fields carry their own ids)
  "body": "Tell us about yourself",      // OPTIONAL
  "fields": [                            // REQUIRED, 1..10
    { "id": "name", "label": "Your name", "placeholder": "…", "required": true }
  ],
  "submit_label": "Submit"               // OPTIONAL, defaults to "Submit"
}
```
- Renders: inline labelled text fields + submit button. v0 `input` primitive is **text only**.
- `values`: `{ "<field id>": "<string value>", … }` (every field, empty string if untouched)
- Auto summary: `"Your name: Asha"` pairs joined with `", "`.

### Primitives (internal vocabulary these blocks are composed from)

`text` (static copy), `image` (url + alt), `input` (text entry, v0 text only),
`option` (id + label + optional image). Not independently addressable as components in v0.

## 7. Validation and limits

Applied at template save (staff console + backend) and on response receipt (backend):

| Rule | Value |
|------|-------|
| Outbound envelope size | ≤ 64 KB serialized |
| Inbound response size | ≤ 16 KB serialized |
| `summary` length | ≤ 500 chars |
| JSON depth | ≤ 10 |
| `component` format | `^[a-z0-9_]+/[a-z0-9_]+$` |
| `glific/*` names | must exist in the catalog above |
| `fallback` | required, non-blank, on every template and every translation |
| `glific/*` props | validated against the block schema at save |
| `glific/*` values | validated against the block's values shape on response |

Response acceptance additionally requires, in this order:
1. the socket's authenticated contact owns `message_id`;
2. that message is `type: :custom_ui` and **not yet answered**;
3. envelope validation above.

Single-submit must be **atomic** — a guarded `update_all` that only marks unanswered messages
and acts on the returned row count, not a read-then-write check.

## 8. Unsupported channels

`Glific.Channels.ChannelCapability.supports?(channel, :custom_ui)` — `true` only for `"web"` in
v0. When a custom_ui send targets an unsupported channel, send the **fallback text as a plain
text message** and raise a `FlowContext.notification`. This must intercept BEFORE
`Communications.Message.@type_to_token`, which has no catch-all and would raise on `:custom_ui`.

In `lib/glific/templates/interactive_templates.ex`:

| Function | Problem for `custom_ui` |
|---|---|
| `generate_csv_data/1` (:1049) | `case` with **no catch-all** → `CaseClauseError` |
| `import_interactive_template/2` (:1286) | same, **no catch-all** → `CaseClauseError` |

| `check_options/1` (:180) | catch-all `:ok` → markdown guard silently skipped |

| `get_clean_interactive_content/3`, `clean_template_title/1`, `process_dynamic_interactive_content/3`, `trim_content/2` | passthrough catch-alls — verify passthrough is actually correct for an envelope |

Elsewhere:
- `Communications.Message.@type_to_token` (`communications/message.ex:26`) — no catch-all.
- `Communications.WebMessage.@type_to_token` (`communications/web_message.ex:27`) — add
  `custom_ui: :send_custom_ui`.
- `WebMessage.do_receive_message/3` (:88-110) — anything not `[:text, :quick_reply, :list]` or
  `:location` falls into `receive_media`, which is wrong for a custom_ui response.
